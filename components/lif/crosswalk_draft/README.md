# `crosswalk_draft` — Component

Pure, standard-library-only generator of **Draft transformation-group bundles** between two MDR data models — e.g. a
district's LIF model and a community college's LIF model. It proposes one JSONata transformation per target
attribute it can match; humans finish the draft in the MDR mapping editor.

Two match sources:

1. **identity** — the attribute's full dotted name path (`Person.Contact.Email.emailAddress`) exists in both
   models. Both models usually derive from base LIF, so most attributes match this way.
2. **crosswalk** — an optional EDUcore-derived JSON (`properties` + `values`, anchored on CEDS). Property rows
   become transformations with `Alignment = "educore:<matchType>:<confidence>:<cedsKey>"`; value rows wrap the
   source term in `$lookup({...}, term)` so unmapped values pass through as null, but only when BOTH
   sides match: the source attribute is the row's `sourceOptionSet` (by name, or by its enum equalling the
   row values) AND the target attribute is the row's `targetOptionSet`. A target-only hit would wrap a
   LIF-to-LIF copy in an Ed-Fi lookup and null out real values. Rows below `min_confidence`
   are dropped and reported.

3. **authored** — rules from one or more exported MDR transformation groups (`--authored` on the CLI, repeatable;
   the first file listed wins a contested target), kept verbatim and re-pointed at the two models by
   `UniqueName`; EDUcore value lookups are folded into a rule when its bare source term appears exactly once.
   A rule's own `Notes` travel with it; rules without Notes get `seeded from authored rule '<name>'`.
   Provenance lands in `Alignment`: `identity`, `educore:<matchType>:<confidence>:<cedsKey>`,
   `<authored_label>` or `<authored_label>+educore-values`.
4. **notes overlay** — `rule_notes` (`--notes` on the CLI): a JSON object keyed by target path. A string is the
   rule's `Notes`; an object may carry `Notes`, `SourceAttributeNotes` (by source `UniqueName`) and
   `TargetAttributeNotes`. Authored rules take the note verbatim; generated rows keep their provenance text and
   get it appended. Keys that match no rule are reported as `notesUnmatched`, so a typo cannot drop a note silently.

Ed-Fi descriptor tolerance: crosswalk `sourcePath`/`sourceOptionSet` names ending in `Descriptor` resolve
to the MDR attribute with the same stem (`Address.StateAbbreviationDescriptor` -> `Address.StateAbbreviation`,
`GradeLevelDescriptor` -> `OfferedGradeLevel`) — only for enum-less sources, so a LIF-valued source never
receives an Ed-Fi-keyed lookup.

## Public surface

```python
from lif.crosswalk_draft import generate_draft_bundle

bundle, report = generate_draft_bundle(
    source_openapi, target_openapi, group_name="District -> College", crosswalk=crosswalk, min_confidence=0.5
)
```

| Symbol | Purpose |
|---|---|
| `generate_draft_bundle(source, target, *, group_name, group_version="0.1", publisher="crosswalk_draft", crosswalk=None, min_confidence=0.5, authored=None, authored_label="lif-authored", rule_notes=None)` | Returns `(bundle, report)`. Inputs are MDR OpenAPI exports (`include_attr_md`, `include_entity_md`, `full_export` on) or data-model bundles whose `dataModel.openapi` holds one. |

## Output contract

```json
{
  "manifest": {"kind": "transformation-group", "formatVersion": "1", "publisher": "...", "exportedAt": "...Z",
               "name": "...", "version": "0.1", "checksum": "sha256:..."},
  "sourceDataModel": {"name": "...", "version": "...", "type": null, "description": "...", "openapi": {...}},
  "targetDataModel": {"...": "..."},
  "transformationGroup": {"Name": "...", "GroupVersion": "0.1", "Description": "Draft generated by crosswalk_draft — review required",
                          "Notes": "identity=…; crosswalk=…; …", "Transformations": [ ... ]}
}
```

Each transformation carries `Name` (target dotted path), `Expression`, `ExpressionLanguage: "JSONata"`,
`Alignment`, `Notes`, `SourceAttributes[].EntityIdPath` and `TargetAttribute.EntityIdPath` — the same
portable shape `POST /transformation_groups/{id}/import` accepts (`{DataModelId}:{~}{UniqueName}` segments,
numeric prefixes ignored, resolution by `UniqueName`).

The report is `{"identityMatches", "crosswalkMatches", "authoredMatches", "valueLookupsApplied", "unmatchedSource",
"unmatchedTarget", "belowConfidence", "authoredSkipped", "notesApplied", "notesUnmatched"}`.

## Expression rules (mirrors `MappingsView.tsx` + `reference_data/transformations/`)

- Target root entity iterates the source root entity: `{ "Person": Student. { ... } }`.
- Nested target entities with `"Array": "Yes"` are wrapped `[{ ... }]`; non-array ones `{ ... }`.
- The source term is the source path relative to its root (`Contact.Email.emailAddress`).
- Inlined `Reference`-placement copies (`RefCourse` whose `Name` is still `Course`) are skipped.
