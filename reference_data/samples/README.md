# Sample records

Hand-written records in the shape of a specific MDR data model, used by demos and scripts. They are
fictional and contain no real people.

| File | Shape | Used by |
|------|-------|---------|
| `northgate-edfi-v5-student.json` | The MDR's `Ed-Fi v5` data model (entities as seeded by `projects/lif_mdr_database/backup.sql`) plus the real Ed-Fi `Student` name elements `FirstName` / `MiddleName` / `LastSurname`, which `scripts/align-edfi-student-model.py` adds to the published model (the seed has a single `Student.Name` string, which Ed-Fi does not) | The schema-exchange Ed-Fi scenario in `docs/design/cross-cutting/schema-exchange.md`: translated into a college LIF model through the LIF-authored + EDUcore-informed draft mapping. One `Course` row on purpose (see the `_comment` in the file). |
| `northgate-edfi-name-rules.json` | An exported-transformation-group-shaped file with three LIF-authored rules for those name elements: `firstName` and `lastName` as direct copies, and `initials` built 3:1 from `FirstName` + `MiddleName` + `LastSurname` | Passed to `scripts/generate-crosswalk-draft.py` as the first `--authored` file so its rows win the name targets over the reference Ed-Fi rules, which split `Student.Name`. Each rule's `Notes` (rationale / caveat) travels into the MDR. |
| `northgate-edfi-rule-notes.json` | Transformation notes for the whole Ed-Fi -> Riverbend draft, keyed by rule Name (target path): a string is the rule's `Notes`; an object may add `SourceAttributeNotes` (by source UniqueName) and `TargetAttributeNotes`. Direct copies say so; rules inherited from the reference file that look wrong are marked `REVIEW` with the reason | Passed to `scripts/generate-crosswalk-draft.py` as `--notes` so the notes ride inside the exchange bundle and land in the MDR's `Notes` fields at group, rule, and attribute level. Authored rules take the note verbatim; EDUcore rows keep their provenance text and get it appended. |
| `northgate-edfi-export-rules.json` | Four LIF-authored rules for the export direction, StateU LIF -> Northgate Ed-Fi v5, covering the Student identity elements the Ed-Fi Data Standard defines (checked against the EDUcore Ed-Fi graph): `firstName -> Student.FirstName`, `lastName -> Student.LastSurname`, a 2:1 `Student.StudentUniqueId` that selects the school-assigned identifier, and an entity-level rule that turns each `Person.Identifier` row into one paired `StudentIdentificationCode` object (IdentificationCode + StudentIdentificationSystem descriptor value + AssigningOrganizationIdentificationCode) | First `--authored` file when drafting the district's export group. Replaces the reference rules that copied identifier and identifierType independently into parallel arrays, and the `Student.Name` / `Student.UniqueId` copies, whose attributes `scripts/align-edfi-student-model.py` retires. |
| `northgate-edfi-export-rule-notes.json` | Notes for the export direction: the rules whose behavior is not obvious from the JSONata (UniqueId without an identifierType check, `Georgia` copied into a two-letter descriptor slot, `Address.Period` built from one of two dates, ...) | `--notes` for the export draft. Plain copies keep the generated marker. |

LIF-shaped learner records live in `projects/mongodb/sample_data/`, not here.
